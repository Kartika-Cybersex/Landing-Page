Alur kerja

Dari sinyal ke laporan, dipandu penuh

Detektor berjalan terus-menerus. LLM dipanggil hanya untuk insiden yang sudah diringkas, jadi cepat dan hemat biaya.

01

Collect & Normalize

Collector read-only membaca auth, web, proses, dan koneksi, lalu menyeragamkan jadi event JSON.

02

Detect & Aggregate

Aturan deterministik dan skor anomali, lalu event terkait digabung jadi satu kandidat insiden.

03

Analyze

LLM menilai true/false positive, menyusun hipotesis, dan memetakan ke MITRE ATT&CK.

04

Decide & Preserve

Policy Engine memutuskan aksi. Bukti disalin dan di-hash sebelum apa pun diisolasi.

05

Respond & Verify

Aksi dari katalog tertutup dijalankan setelah Anda setuju, lalu hasilnya diverifikasi.

06

Report

Timeline, akar masalah, dan draf notifikasi UU PDP atau eskalasi ke BSSN siap ditinjau.

    Aman secara desain

    Alat keamanan tidak boleh menambah risiko

    Katalog aksi tertutup

    LLM hanya memilih dari daftar aksi dengan parameter tervalidasi. Tidak pernah menulis perintah shell.

    Kebal prompt injection

    Log diperlakukan sebagai data tak tepercaya. Output wajib JSON berskema, keputusan akhir di Policy Engine.

    Anti salah blokir

    Protected list untuk IP admin dan gateway, TTL pada setiap blokir, batas aksi per jam, dan tombol /pause.

    Persetujuan terikat

    YA/TIDAK terikat ke ID aksi, kedaluwarsa dalam menit, dan hanya dari user chat yang terdaftar.

    Privasi data

    Password dan PII dimasking sebelum ke LLM. Tersedia opsi model lokal dan retensi yang bisa diatur.

    Tetap jalan tanpa LLM

    Jika API mati atau kuota habis, aturan deteksi dan pertahanan dasar tetap bekerja.

    Fitur

    Untuk pengelola IT yang merangkap segalanya

    Deteksi berlapis

    Brute force SSH, webshell, perubahan file kritis, proses mencurigakan, dan koneksi keluar yang janggal.

    Khusus WordPress

    wp-login, xmlrpc, plugin rentan, dan user admin baru, serangan yang paling sering menimpa UMKM.

    Korelasi multi-sumber

    Login berhasil, user baru, cron aneh, dan koneksi keluar disatukan jadi satu cerita insiden.

    Playbook CSIRT

    Ransomware, phishing, defacement, kebocoran data, DDoS, dan malware, dipandu langkah demi langkah.

    Kontrol via chat

    Telegram, Discord, Slack, atau email. Tanya "kenapa IP ini diblokir?" dengan bahasa sehari-hari.

    Dokumen siap pakai

    Timeline, laporan pasca-insiden, draf notifikasi UU PDP, dan draf eskalasi ke BSSN.

    Kepatuhan

    Dokumentasi insiden yang rapi sejak hari pertama

    Setiap insiden menghasilkan jejak audit: waktu, bukti, aksi, dan siapa yang menyetujui. Draf dokumen membantu Anda, keputusan hukum tetap di tangan manusia.

    UU PDP

    Draf notifikasi dan catatan akuntabilitas pemrosesan data.

    BSSN

    Draf laporan eskalasi ke Gov-CSIRT atau ID-SIRTII sesuai sektor.

    NIST SP 800-61

    Alur penanganan insiden sebagai acuan playbook.

    ISO 27001

    Bukti pemantauan dan penanganan insiden untuk audit.

    Tiga langkah menuju pertahanan yang proper

    1

    Pasang collector

    Install collector read-only di VPS Anda, hubungkan ke host SENTINEL, dan daftarkan akun chat admin.

    2

    Atur protected list

    Daftarkan IP admin dan gateway, pilih mode safe, lalu biarkan periode belajar membentuk baseline.

    3

    Setujui lewat chat

    Terima insiden lengkap dengan timeline dan usulan aksi, tinggal tekan YA atau TIDAK.

    Pertanyaan yang sering diajukan

    Apakah SENTINEL bisa memblokir IP yang salah?+

    Risikonya ditekan lewat protected list, TTL pada setiap blokir, batas aksi per jam, dan mode safe sebagai default. Hanya aksi sempit dan reversibel yang boleh otomatis.

    Apa bedanya dengan fail2ban?+

    fail2ban memblokir pola tunggal. SENTINEL menghubungkan beberapa sinyal menjadi satu insiden, menjelaskan akar masalahnya, memandu respons, dan menyusun dokumentasi. Keduanya saling melengkapi.

    Ke mana data log saya dikirim?+

    Data dimasking lebih dulu, dan yang dikirim ke LLM adalah ringkasan insiden, bukan log mentah. Anda bisa memilih model lokal untuk menjaga data tetap di infrastruktur sendiri.

    Apakah ini menggantikan tim CSIRT?+

    Tidak. SENTINEL memperkuat satu orang IT agar bekerja seperti tim kecil. Monitoring 24/7, forensik mendalam, dan tanggung jawab hukum tetap membutuhkan manusia dan pihak eksternal.

    Server apa yang didukung?+

    Versi awal fokus pada VPS Linux dengan akses root atau sudo terbatas. Shared hosting tanpa akses root belum didukung.

    Apa yang terjadi jika API LLM mati?+

    Deteksi dan pertahanan dasar berbasis aturan tetap berjalan. Hanya analisis dan penjelasan cerdas yang tertunda.
